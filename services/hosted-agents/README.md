# Hosted Agents

`@agentfuel/hosted-agents` owns authenticated Agent configuration, local wallet custody, budget reservations, durable runs and safe public status. Its executors support two different economic paths: escrow-backed programming tasks that can earn and repay, and cash-funded personal goals that produce artifacts. Bounded sessions can acquire resources through games, goals can hire approved external services, and new model calls can downgrade within the same task/mission when resources are tight. The [architecture guide](../../docs/ARCHITECTURE.md) explains payment, verification and trust boundaries; [verification](../../docs/VERIFICATION.md) indexes source, tests and dated reports.

## Follow a request

The browser uses the same-origin `/api/hosted/*` proxy. [HTTP routes](src/http.ts) authenticate the bearer session before passing the owner to [HostedService](src/service.ts); callers cannot supply another owner, a private key or arbitrary provider/RPC endpoints. Login signs a nonce/origin/chain/expiry challenge. The service generates a separate hosted wallet, stores its key locally with restricted permissions and binds Agent operations to the authenticated owner.

Creation may start with only a name; execution waits for provisioning and confirmed settings. Requests bind their UUID and original parameters, reserve the configured budget and retain one active run per Agent. Replaying the same UUID recovers that run. Interrupted runs become `Paused`, retaining unresolved reservations. The platform owns the hosted signer; user configuration and contract policy bound its execution, but this is not self-custodial session-key access.

| Path | Main implementation | Acceptance and accounting |
| --- | --- | --- |
| `task`, `reward-task`, `metered-task` | [Task executor](src/task-executor.ts), [Pi workflow](../../packages/pi-loop/src/workflow.ts) | Catalog selection/acceptance, bounded Pi tools, separate hidden Docker tests and a separate settler. Canonical `TaskSettled` and task/loan state support success, repayment and income. |
| `autonomous` | [Autonomy executor](src/autonomy-executor.ts), [bounded controller](../../packages/pi-loop/src/autonomy.ts) | Validated `run-task`, configured `run-game` or `stop`, bounded by model/funding/time/task/game/spend limits. Paid planning uses cash; a host policy can bootstrap or replenish resources without a planner call. Child tasks retain separate Docker acceptance and settlement. |
| `goal` | [Goal executor](src/goals/executor.ts), [commander](src/goals/commander.ts), [paid calls](src/goals/payment.ts) | 1–3 built-in or configured external specialist phases, a separate reviewer call, at most one revision and re-review. All calls use cash with `taskId=0`; no escrow income, loan or reputation increment. |
| `game`, `credits` | [Game executor](src/game-executor.ts) | Supported game rewards/consumption, launched directly or by an enabled autonomous parent. Game entry cannot borrow against an expected reward. Practice games and unsuccessful outcomes do not become real reward credits. |

Goal planning, specialists and reviewer are separate calls with their own saved routes. Before a new quote, the host may choose a cheaper approved model according to remaining mission budget, cash and future phase/review reserves. Earlier outputs remain available; signed or uncertain calls keep their original route and payment. The reviewer is a model check, not Docker execution or a general fact oracle. [Hard acceptance checks](src/goals/acceptance.ts) enforce supported measurable constraints. The [specialist catalog](src/specialists/catalog.ts) defines built-in roles and output contracts; [bounded chain lookup](src/goals/chain-lookup.ts) optionally supplies pinned Monad/Anvil RPC and source evidence. Goal models have no arbitrary web, filesystem, shell, deployments or fund-transfer tools.

[External discovery](src/external/registry.ts) checks operator-approved service advertisements and identity endpoints, admits by exact capability/reputation/budget, then ranks with 70% reputation and 30% price. Optional ERC-8004 identity/reputation is read at a pinned block. The runtime launchers bind services to a separately registered and payment-whitelisted provider. [Hiring](src/external/hiring.ts) binds the original assignment, service/provider, fixed price, payment and returned provenance; [the service adapter](src/external/service.ts) exposes the compatible paid endpoint. External stages cannot substitute an unapproved endpoint or silently become an internal role. Their output still passes the goal's separate review and hard checks. This is configured HTTP collaboration; operators explicitly approve discovery URLs, endpoints, capabilities, models and prices.

When automatic games are configured, reward observations determine whether the parent can continue paid work or use supported model tokens. Count, deadline and per-game/cumulative spend limits apply. A paused reward-funded task can acquire more tokens and resume its original child and escrow acceptance; it is not replaced with a fresh task. The [local acceptance guide](../../docs/autonomous-collaboration-20261014.md) links both reward kinds and original-task replenishment evidence.

Optional `autonomy.games` contains `maxGames`, `maxSpendPerGameRaw`, `rewardKinds` and `rewardTaskMinTokens`. The local and Monad launchers set new sessions to two games, six decisions, zero per-game paid budget, both `usdc`/`llm-credits` rewards and a 2048-token task threshold. Bootstrap/replenishment is a host policy, not a free LLM decision. Owner/global sponsorship limits and durable per-game admission also apply. Exact configuration and startup commands are in the [core runtime guide](../../docs/core-runtime.md#配置与启动); [the acceptance guide](../../docs/autonomous-collaboration-20261014.md) provides the reproducible local runs.

## Prices and recovery

New task snapshots apply the host-owned [economic admission policy](../../docs/ECONOMICS.md#before-accepting-a-task) before accepting work or paying for inference. Older saved snapshots keep their original bindings. The owner-authenticated `GET /agents/:id/accounting` endpoint derives [operating accounts](src/accounting.ts) from retained executions without calling the chain finance reader or modifying history. The Finance panel separates task revenue, net inference expense, borrowing fees, subsidies and capital flows; incomplete evidence withholds a complete operating result. See [accounting semantics and limits](../../docs/ECONOMICS.md#after-execution).

Owner-authenticated `GET /agents/:id/strategy-advice` joins original admissions and realized outcomes with a checked cash snapshot. `POST` on that path calculates an owner-supplied hypothetical candidate set and optional reserve/profit requirements. Both are read-only: no settings, requests or policies are saved, and no executor is called. The [strategy guide](../../docs/STRATEGY-ADVICE.md) explains route binding, conservative loss/cost buffers, evidence gaps and the offline demonstration.

Goals, external hires and task-planning calls use the selected service's fixed price per invocation. `metered-task` instead buys a task-bound allowance package, then [the gateway](src/inference-gateway.ts) reserves and settles microcredits at each model's input/output token rates through Magpie. [The metered adapter](src/metered-task.ts) verifies the paid grant, catalog binding and original task before consumption. Its admission may downgrade a new strong round to cheap only when the full cheaper reserve fits; [Pi](../../packages/pi-loop/src/provider.ts) persists the actual tier while preserving earlier messages/code/tools. Unknown spending freezes cannot be avoided by changing models. Cash, loan principal/fees, gateway microcredits and game-earned model tokens are separate resources.

The host saves payment handles and dispatch intents before crossing payment/model boundaries. Unknown outcomes retain their original UUID, payment and reservations; they pause rather than creating replacements. A cached response can be reused without paying again. [Goal reconciliation](src/goals/reconciliation.ts) requires canonical payment/refund evidence; cancelling a goal does not erase an unresolved payment. [SessionStore](../../packages/pi-loop/src/session.ts) uses atomic snapshots and a single local writer with explicit stale-lock recovery.

Older sessions retain their saved configuration and permissions during compatible recovery. Enabling new automatic-game defaults does not grant an older session more games, decisions, spending or time. Signed, paid and Unknown calls retain the original model route and payment handle; a cheaper model is selected only at an unstarted call boundary.

[Finance reads](src/finance-reader.ts) and [public activity types](src/scene-types.ts) expose checked snapshots and whitelisted evidence. Activities are executor-generated, persisted with increasing sequence numbers and capped at 256 per run. Frontend motion is a view of those facts, not a mechanism for deciding that an operation succeeded.

## Run and inspect

See the [Chinese configuration/API runbook](../../docs/hosted-agents.md), [core runtime](../../docs/core-runtime.md) and [local startup guide](../../docs/local-hosted-testing.md). Runtime configuration, journals, keys and raw model evidence belong in private ignored directories.

From the repository root, with Node 22.19.0+, cached Foundry/solc and the documented Docker dependencies available:

```sh
npm test --workspace @agentfuel/hosted-agents
npm run typecheck:all
```

Source-level checks include [owner/API isolation](test/http.test.ts), [paid goal execution](test/goals-paid.test.ts), [goal reconciliation](test/goals-reconciliation.test.ts), [metered recovery](test/metered-recovery.test.ts), [credit reservation/unknown freeze](test/inference-gateway.test.ts), [autonomy](test/autonomy-executor.test.ts) and [public scenes](test/scenes.test.ts). New paths have [automatic game/task acceptance](test/autonomy-game-live.test.ts), [external discovery/hiring/recovery](test/external-hiring.test.ts), [paid goal downgrade](test/goals-model-fallback-paid.test.ts) and [metered downgrade regression](test/model-fallback.test.ts). The [2026-10-14 reports](../../docs/autonomous-collaboration-20261014.md) use local Anvil contracts, actual local HTTP/signed transactions and controlled LLM responses; automatic task settlement also uses Docker and a separate Arena settler. The separate Monad record establishes identity and whitelist admission for external Provider Agent 1999 only; fresh Monad and live supplier execution of the three integrations remain unverified. [Tracked goal acceptance](../../frontend/acceptance/dashboard-goal-20261013/live-acceptance.md) describes the separate historical real-model run and its limitations.
