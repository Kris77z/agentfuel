# Tabby Agent 全链路场景设计

日期：2026-10-14。状态：2026-10-14 已实施并通过本地集成、浏览器与生产构建验收；验收结果单独记录于 `frontend/acceptance/tabby-scenes-20261014/README.md`。原四阶段预览不能作为全链路验收。

## 角色与展示原则

猫始终代表用户当前选中的托管 Agent。这个 Agent 可以为自己的目标组织专家，也可以承接其他任务；角色随任务变化，身份不变。专家节点代表实际可调用的服务/执行角色，不把内置角色包装成独立链上 Agent。

中间画布一次显示当前场景：猫 + 当前交互对象 + 一行状态；右侧同步选中专家，底部保留输入与必要操作。任务节点、专家节点、模型、资金、游戏对象必须具有不同标识。画布仅展示动画和一行状态，不提供点击、详情、操作按钮或阶段列表；信息与凭证从右栏专家卡和现有请求记录查看。

## 通用中断状态

- 等待用户：缺资料、待配置、待充值或授权。显示具体缺项及唯一主要操作。
- 暂停：用户暂停或策略暂停；不显示仍在调用模型。
- 等待确认：付款/接单/结算尚未确定，显示交易对象和已有凭证。
- 对账中：未知调用、超时、过期付款；显示“结果待确认”，不得直接当失败再次支付。
- 停止中：停止新动作并完成已有付款对账；不是点击停止即已终止。
- 已取消、已失败、已退款：分别展示。退款必须有确认凭证；失败保留已有成果和费用。
- 服务断开或状态过期：最近一次确认状态 + 更新时间；不能把网络断开解释为链上任务失败。
- reduced-motion / 用户关闭动画：只冻结视觉，业务进度和凭证仍正常更新。

显示优先级：停止/对账 > 必须用户处理的阻塞 > 当前真实业务活动 > 完成/待命。历史回放与当前运行明确区分。

## 三类路径

1. 自由目标：目标 → 必要时查链 → 规划 → 匹配专家/选择模型与付费 → 执行 → 复核（必要时修订）→ 交付。当前 goal 为 cash-only，不带托管报酬还款或链上信誉增长。
2. 收益任务：自主或手动选单 → 托管报酬检查与接单 → 资金与授信/模型购买 → 执行 → 验收 → 还款和收入、信誉确认 → 下一轮或停止。
3. 游戏：进入对局 → 执行/等待 → 比赛结果 → 按奖励类型确认 USDC 或模型额度 → 返回任务工作区。练习局、未获奖结果不经过奖励入账。

游戏补给作为按需分支；当前 autonomy 的决策动作是 run-task/stop，不能声称已实现自主去玩游戏补额度。不同执行入口尚不构成一个完全统一的自动编排器。

## 原版核对与实现差距

参考 `/Users/jungle/Desktop/dev/monad-rebel/frontend/src/components/timeline/` 下 `pipeline-snake.tsx`、`timeline-builders.ts`、`snake-engine.ts`。原版消费 services_discovered / service_selected / phase_started / execution_started 等事件，节点携带专家身份、价格和信誉；hunt/idle 控制追逐与游走。原代码部分信誉由插入顺序生成，未选中节点也可映射 failed：只复用交互思路，不照搬这些业务语义。

当前 `mission-progress.ts` 仅映射规划/阶段产出/复核，并将其他 action 压成单个节点；Queued 也被归为 running，未细分 needs-input、修订、资金、游戏、对账，不能支撑以上场景。

需补公开、持久化的 scene/activity 事件投影：requestId、递增序号、发生时间、场景、状态、phaseId、真实交互对象、reason/requiredAction、凭证引用。各 executor 输出经过白名单的公共事件，避免浏览器读私有 journal。已有结果字段继续作为确认依据，不用计时器推测阶段成功。

候选选择、查询、付款、修订、对局和结算事件逐项接入；只有公开事实支持时才展示。测试重点为分支、断线恢复、停止对账、复核失败、游戏非获奖、单笔原子结算；预览覆盖所有状态但显式标为回放。

## 2026-10-14 实施结果与范围

公共 activities 由执行器真实阶段触发，经服务串行持久化与前端代理白名单传递；最多保留 256 条，序号跨重启连续。正式 Dashboard、专家栏和练习游戏已接入。历史回看只读，断线、停止、对账与部分退款不冒充成功。场景预览为 39 个明确标注的样例，复用正式组件，不发送交易。

授信 SDK 内部资格/报价尚无独立细粒度回调，现有信用场景只依据真实融资选择、拒绝与付款回执。REP 显示符合时间和 Agent 约束的财务快照或等待刷新，不推算增长。内置专家不表示全球市场发现，自主模式仍只支持 run-task/stop，不自动去游戏。

验收：后端核心目标组 89/89、本地执行器集成 16/16、前端全组 64/64；跨服务/代理/场景与重启恢复测试通过；root/frontend 类型检查和隔离 Next 生产构建通过。浏览器已检查专家联动、信息入口、无奖励、部分退款对账、历史静止、等待/暂停和窄屏布局。本轮没有新增付费模型调用或 Monad 交易。

### 2026-10-14 运动修正

用户验收指出固定位置换表情不符合原 snake/Magpie 的运动体验。对照 monad-rebel `pipeline-snake.tsx` 的追逐/待机循环及本项目 `magpie-flight.ts` 后，场景新增持续位置状态：寻找专家时依次巡视候选，选中后在该专家附近移动，其他运行场景到达交互对象后切换动作；待命慢速散步。四帧步态、朝向与短脚印轨迹随位移更新，动画进度由 ref 保留，不触发 React 每帧重渲染。节点与猫使用上下分开的区域，避免文字重叠。

运动只负责视觉，不写入活动、不会凭接近节点判定成功。历史回放、业务暂停、断线与 reduced-motion 保持静止；手动暂停冻结本地时钟，恢复不跨越后台时间。

### 2026-10-14 纯展示区域修正

按用户反馈再次对照原版 `pipeline-snake.tsx`（canvas + evalLabel）与 Magpie：中间场景改为纯展示。移除节点按钮/悬浮边框、面板按钮、信息与凭证折叠区及内嵌阶段列表。真实活动记录、右栏自动选中专家、右栏个人信息卡与请求凭证保留；猫持续移动，历史请求、业务暂停、断线、reduced-motion 仍静止。此决定取代此前“点击节点查看详情”和“画布内阶段选择”的设计。

### 布局平衡修正

对象不再集中于画布右半侧，改为等宽列居中分布：单节点居中，多节点沿整个画布均匀排布，左右留白对称。巡视路径使用同一组节点坐标，静态回放的猫居中。浏览器已复核三个候选布局，运动边界和目标巡视测试 2/2 通过；截图见 `frontend/acceptance/tabby-scenes-20261014/balanced-canvas.png`。

### 节点接触与收取

单纯巡视不再代表完整交互。运动增加 approach → inspect → pounce → absorb → retreat → rest：猫与节点处在同一行动区域，候选嗅探会发光回应；真实 selected 专家可被扑取，节点缩小消失并保留已选标记，猫携带能力标记离开。执行中的 OUTPUT 不可收取，只有阶段 completed 后才可扑取结果；未完成/失败/对账不产生成功收取。收取按当前活动只发生一次，动画不改变后端状态。历史、断线和 reduced-motion 静态展示不播放收取。

预览增加“播放专家协作”，在同一请求中演示寻找、选定、执行、产出确认、交付，明确为样例；画布本身仍无点击控件。
