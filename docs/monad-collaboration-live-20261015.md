## Runtime blockers corrected and deployed

Fresh task preparation exposed an expired host-template deadline: the runtime still generated new workflows from the original `journal.templateDeadlineMs`, even after an audited task-catalog append. A new task could therefore stop with `WORKFLOW_DEADLINE` before starting.

The [runtime correction](../scripts/monad-hosted-runtime.ts) computes a **new request template's** deadline as the maximum of the original journal deadline and the deadlines in the validated task catalog. It does not write a later deadline into the journal, move recovery bindings, or rewrite existing request snapshots. Restarting alone does not renew an expired catalog. The task executor continues to freeze a deadline for each newly admitted request and use that original snapshot on recovery.

The append path also originally required every Hosted run to be terminal. It now admits only strictly verified, unsigned, zero-charge `provision` pauses: the original Agent and request IDs, owner, wallet, canonical snapshot binding, direct Monad domain and empty transaction journal must all match. Paid or Unknown calls, signed transactions, active task work, `Queued` and `Running` requests remain blocked. Database and paused-snapshot bytes are guarded again before migration writes; appending a catalog does not resume any Agent.

The [runtime regressions](../scripts/test/monad-hosted-runtime.test.ts) and [deployment-migration regressions](../scripts/test/monad-vps-migrate.test.ts) passed **23/23**, including an actual local Anvil payment followed by an Unknown model response. After its original request deadline elapsed and a newer template became available, recovery preserved the original snapshot, config, child config, payment handle, transaction records and binding. The request remained Unknown, retained its original `120000` charge, and caused no additional model dispatch or wallet nonce. Append regressions also preserved all five admitted paused requests and wallet-file bytes, rejected 16 unsafe state variants, and detected later database/snapshot byte changes. Workspace TypeScript checking and the changed-file whitespace check passed.

These are local regression checks for the deployed corrections. The fresh Monad business outcomes are recorded separately below.

## Exhausted task catalog: successful stop after useful work

Review of the automatic path exposed a second completion risk: with `maxTasks=2` and only one executable catalog task, a successful first task could be followed by an unnecessary reward-task request and `NO_FEASIBLE_CANDIDATE`. The [hosted runtime](../services/hosted-agents/src/autonomy-executor.ts) now checks availability at a fresh game-enabled decision boundary only after at least one task has completed and while no accepted task is pending.

It uses the existing trusted provider to read catalog tasks and loans at the finance observation's canonical block, verifies the chain/domain and task deadlines, checks configured execution capabilities, and rechecks the block after reading. A confirmed empty catalog produces the zero-charge runtime decision `AUTONOMY_NO_AVAILABLE_TASKS`: phase `Stopped`, `success=true`, with the completed-task count retained. RPC failures, chain mismatches or reorganizations pause with `AUTONOMY_OBSERVATION_UNAVAILABLE`; they never prove an empty queue. Existing pending children keep their original IDs and are resumed before this decision. No task count, game quota, budget or saved paid snapshot is increased.

Hosted autonomy regressions passed **39/39**. A separate actual Anvil + HTTP + Docker + independent-settler regression passed **1/1**: a two-task parent completed its sole configured task, verified canonical settlement, then stopped successfully with one game and one task, without creating another planner call or child. Replay caused no model request or wallet nonce. Tests also cover remaining open work, unavailable/noncanonical reads and original pending-task recovery. TypeScript and changed-file whitespace checks passed. This correction was deployed before the successful public task 19 recheck, whose parent stopped for the same confirmed empty-catalog reason.
